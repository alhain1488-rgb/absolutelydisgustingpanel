## Зафиксированные решения / для сведения

### Hysteria2 не поддерживается в MVP
Hysteria2 — QUIC-протокол проекта Hysteria; его сервер **не реализован в
xray-core**, поэтому он не может быть inbound-ом в `config.json` Xray. В
SSH-конфиг-механизме MVP он не поддерживается. Реестр протоколов спроектирован
так, чтобы адаптер Hysteria2 (поверх отдельного бинарника hysteria / sing-box)
можно было добавить позже без изменения схемы БД. Если Hysteria2 нужен —
требуется явное решение человека о запуске отдельного демона на нодах.

### Shadowsocks: один метод/пароль на inbound (без per-client identity)
Классический Shadowsocks (например, `aes-256-gcm`) не поддерживает несколько
пользователей на одном порту с раздельными паролями. Поэтому SS-inbound хранит
**один** сгенерированный `method`+`password`, общий для всех клиентов, которым
выдан доступ к этому inbound-у. Для персонального использования это приемлемо;
per-client identity обеспечивают остальные протоколы (VLESS/VMess/Trojan). При
необходимости раздельных SS-пользователей — миграция на 2022-blake3 ciphers
(отдельное решение, схему БД не меняет: параметры в `settings_json`).

### Интеграция с реальным Xray (`xray -test`) — вне автономной среды
В автономной среде разработки Docker-демон недоступен, поэтому живой прогон
`xray -test` не выполняется здесь. Инфраструктура готова: `test/xray-node`
(Docker-образ Go + xray) и интеграционный тест под тегом `integration`
(`backend/internal/xrayconfig`). Прогон делается человеком/CI там, где есть
Docker или бинарник `xray` (см. `test/xray-node/README.md`). Структурная
корректность генерации конфига покрыта обычными юнит-тестами.

## Требует человека (из ROADMAP §«Что требует человека»)

1. Заполнение `.env` реальными секретами (`PANEL_ENCRYPTION_KEY`,
   `PANEL_JWT_SECRET`, логин/пароль админа, `PANEL_DOMAIN`).
2. Реальные SSH-ключи и доступ к VPS. Разработка/тесты — только на моках и
   локальной dockerized-ноде Xray.
3. DNS/домен и выпуск TLS (Caddy авто-выпустит при корректном DNS на VPS).
4. Решение по Hysteria2 (см. выше), если нужен.
5. Финальный деплой на прод — после ревью человеком.
