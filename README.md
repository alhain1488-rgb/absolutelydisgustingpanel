# Xray Panel

Веб-панель для **личного** централизованного управления несколькими VPS с Xray:
серверы, inbound-ы разных протоколов, клиенты и их подписки. Одна панель на
главном VPS управляет Xray на всех серверах по SSH (генерация `config.json` →
валидация `xray -test` → рестарт). Без биллинга, лимитов трафика и
мультиарендности.

**Стек:** Go (backend) · React + TypeScript (frontend) · SQLite · Docker Compose · Caddy (TLS).

- Клиент получает доступ **не к серверу целиком, а к конкретным inbound-ам**
  (связь многие-ко-многим).
- Подписка собирается автоматически из всех разрешённых и включённых inbound-ов
  клиента на всех серверах и отдаётся по единственному публичному эндпоинту
  `GET /sub/{token}`.
- Секреты (SSH-ключи/пароли, TOTP) шифруются at-rest (AES-256-GCM); пароль
  админа — только bcrypt.

## Возможности

- Аутентификация: логин (bcrypt) + опциональный TOTP (2FA), rate-limit, аудит
  всех действий.
- Серверы: CRUD, проверка доступности, IP + геолокация, статус Xray, рестарт,
  метрики CPU/RAM/диск по SSH.
- Inbound-ы: VLESS (Reality/TLS), VMess, Trojan, Shadowsocks; ключи Reality
  генерируются на бэкенде; параметры протокола в JSON-полях.
- Клиенты: создание одной кнопкой (UUID/пароль/токен), выдача доступа к
  inbound-ам чекбоксами, подписка + QR + скачивание, ротация токена,
  включение/выключение.
- Sync-движок: сборка полного `config.json` и пуш по SSH (бэкап → запись →
  `xray -test` → рестарт), идемпотентность по хэшу.
- Dashboard, журнал действий, тёмная/светлая тема, Swagger.

## Требования

- Docker + Docker Compose (для продакшн-запуска), либо Go 1.24+ и Node 22+ (для
  локальной разработки).
- Домен, указывающий на главный VPS (для авто-TLS через Caddy/Let's Encrypt).
- SSH-доступ к управляемым VPS (ключ или пароль); на каждом установлен Xray и
  systemd-сервис `xray`.

## Быстрый старт

```bash
cp .env.example .env      # заполнить секреты (см. ниже)
docker compose up --build
```

После старта панель доступна по HTTPS на вашем `PANEL_DOMAIN`. Первичный админ
создаётся из `PANEL_ADMIN_USERNAME` / `PANEL_ADMIN_PASSWORD` при первом запуске.

Проверить работоспособность запущенного backend можно смоук-скриптом:

```bash
BASE_URL=https://your-domain ADMIN_USER=admin ADMIN_PASS=... ./scripts/smoke.sh
```

## Переменные окружения

Обязательные (панель падает с понятной ошибкой, если не заданы):

| Переменная | Назначение |
|---|---|
| `PANEL_ENCRYPTION_KEY` | Мастер-ключ AES-256-GCM, 32 байта base64 (`openssl rand -base64 32`). Шифрует SSH-секреты и TOTP. |
| `PANEL_JWT_SECRET` | Секрет подписи JWT (`openssl rand -base64 48`). |
| `PANEL_ADMIN_USERNAME` | Логин первичного админа. |
| `PANEL_ADMIN_PASSWORD` | Пароль первичного админа (хэшируется bcrypt, не хранится в открытом виде). |
| `PANEL_DOMAIN` | Домен панели (Caddy авто-TLS, базовый URL подписки). |
| `DB_PATH` | Путь к файлу SQLite (в volume). |

Опциональные:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PANEL_HTTP_ADDR` | `:8080` | Адрес прослушивания backend. |
| `LOG_LEVEL` | `info` | `debug`\|`info`\|`warn`\|`error`. |

> Панель никогда не выдумывает секреты и не хардкодит их — всё читается из
> окружения. `.env` заполняет человек.

## Подключение реального VPS

1. Установите на VPS Xray и systemd-сервис (по умолчанию имя `xray`, путь
   конфига `/usr/local/etc/xray/config.json` — настраивается при создании
   сервера).
2. В панели: **Servers → Add server**, укажите host, SSH-пользователя и
   ключ/пароль (секрет шифруется при сохранении).
3. Нажмите **Check** — панель проверит доступность, определит IP/гео и статус
   Xray.
4. Создайте inbound-ы (**Server → Add inbound**). Для VLESS Reality ключи и
   shortId генерируются автоматически.
5. Создайте клиента, выдайте ему нужные inbound-ы, скопируйте subscription-ссылку
   или QR. Любое изменение автоматически пушится на затронутые серверы
   (`config.json` → `xray -test` → рестарт).

> Панель управляет только фиксированными путями/командами из записи сервера и
> ничего не разворачивает на чужой инфраструктуре сама.

## Добавление нового протокола

Знание о протоколе живёт в одном месте — реестр `backend/internal/protocols`:

1. Реализуйте интерфейс `Protocol` (`Name`, `BuildInbound`, `BuildLink`) в новом
   файле пакета.
2. Зарегистрируйте адаптер в его `init()` через `register(...)`.
3. **Схему БД менять не нужно** — протокол-специфичные параметры хранятся в
   JSON-полях inbound-а (`settings_json` / `stream_settings_json`).
4. Добавьте адаптер в интеграционный набор `test/xray-node`, чтобы конфиг
   проходил `xray -test`.

Про Hysteria2: его сервер не реализован в xray-core, поэтому inbound-ом в
`config.json` он быть не может — в MVP не поддержан (см. `docs/QUESTIONS.md`).

## Troubleshooting

- **Панель не стартует, «missing required environment variables»** — не заполнен
  `.env`. Сгенерируйте ключи (`openssl rand -base64 32` / `48`) и задайте все
  обязательные переменные.
- **`PANEL_ENCRYPTION_KEY must decode to 32 bytes`** — ключ не 32 байта после
  base64-декодирования; сгенерируйте заново.
- **Caddy не выпускает сертификат** — проверьте, что `PANEL_DOMAIN` указывает
  A/AAAA-записью на этот VPS и порты 80/443 открыты.
- **Сервер offline после Check** — проверьте host/порт/SSH-креды; секрет должен
  соответствовать выбранному методу (ключ PEM vs пароль).
- **`last_sync_error` на сервере** — Xray отверг конфиг или недоступен по SSH;
  панель восстанавливает предыдущий конфиг из бэкапа при провале `xray -test`.
- **Пустая подписка** — клиент выключен, либо у него нет включённых inbound-ов на
  включённых доступах.
