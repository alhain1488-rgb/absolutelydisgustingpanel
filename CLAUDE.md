# CLAUDE.md

Этот файл Claude Code читает автоматически в начале каждой сессии. Здесь — только то,
что нельзя вывести из кода: правила работы, инварианты архитектуры и команды.
Полное ТЗ — в `docs/SPEC.md`, пошаговый план — в `docs/ROADMAP.md`.

## Что мы строим

Веб-панель управления несколькими VPS с Xray для **личного использования**. Одна панель
на главном VPS централизованно управляет Xray на всех серверах по SSH: серверы, inbound-ы
разных протоколов, клиенты и их подписки. Никакого биллинга, оплат, лимитов трафика,
рефералок — этого в проекте нет и быть не должно.

Стек: **Go** (backend) · **React + TypeScript** (frontend) · **SQLite** · **Docker Compose**.

## Как ты работаешь над этим проектом (правила, обязательны к соблюдению)

1. **Идём строго по `docs/ROADMAP.md`, фаза за фазой. Не забегай вперёд.** Внутри фазы
   можешь планировать свободно.
2. **Завершение фазы = ритуал:** прогнать команды проверки из фазы → убедиться, что всё
   зелёное (тесты, `go vet`, линтер) → `git commit` по Conventional Commits → дописать
   короткую запись в `docs/PROGRESS.md` (что сделано, что проверено) → перейти к следующей фазе.
3. **Никогда не подключайся к реальным серверам и ничего не разворачивай на них.** Никаких
   `ssh`/`scp`/`sudo` в чужую инфраструктуру. Вся работа с серверами при разработке идёт
   через моки (интерфейсы) и локальную dockerized-ноду Xray в `test/`. Финальную интеграцию
   с реальными тремя VPS человек делает сам.
4. **Не выдумывай секреты.** Ключи, пароли, домен, SSH-ключи читаются из окружения. Если
   обязательная переменная не задана — падай с понятной ошибкой. Ничего не хардкодь.
5. **Backend и frontend строго разделены.** Общаются только через REST API и
   сгенерированные типы. Никакой общей кодовой базы.
6. **Новый протокол добавляется ТОЛЬКО через реестр протоколов** (`internal/protocols`).
   Схема БД при добавлении протокола **не меняется** — протокол-специфичные параметры живут
   в JSON-полях. Если для нового протокола хочется новую колонку — это ошибка дизайна, стоп.
7. **Тесты пишутся вместе с кодом.** Фаза не закрыта, пока её тесты и линтер не проходят.
8. **Миграции аддитивные и применяются автоматически при старте.** Уже применённую миграцию
   не редактируем — добавляем новую.
9. **Если реально заблокирован** (нужен настоящий секрет, нужна реальная инфраструктура, или
   решение не покрыто спецификацией) — не угадывай. Запиши вопрос в `docs/QUESTIONS.md`,
   сделай что можешь без этого, и остановись на этом пункте.
10. **Язык:** код, комментарии и коммиты — на английском. Плановые документы (`docs/*.md`,
    этот файл) — на русском.

## Инварианты архитектуры (нарушать нельзя)

- **Модель доступа:** клиент получает доступ не к серверу целиком, а к конкретным inbound-ам.
  Связь `clients` ↔ `inbounds` — многие-ко-многим через `client_inbounds`.
- **Подписка собирается автоматически** из всех разрешённых и включённых inbound-ов клиента
  на всех серверах. Это единственный публичный (по токену) эндпоинт: `GET /sub/{token}`.
- **Секреты шифруются at-rest** (AES-256-GCM, мастер-ключ из `PANEL_ENCRYPTION_KEY`):
  SSH-ключи/пароли, TOTP-секрет. Пароль админа — только bcrypt-хэш.
- **Протоколы MVP — только те, что нативно поддерживает xray-core:** VLESS (Reality и TLS),
  VMess, Trojan, Shadowsocks. **Hysteria2 в xray-core как inbound не существует** (это QUIC-протокол
  проекта Hysteria / sing-box) — он заложен в реестр как будущий адаптер, но в MVP не реализуется
  в конфиге Xray. Подробности и обоснование — в `docs/SPEC.md`.

## Команды

Backend (из `backend/`):
```
go run ./cmd/panel        # запуск локально
go test ./...             # тесты
go vet ./...              # статический анализ
gofmt -l .                # проверка форматирования
golangci-lint run         # линтер (go install при отсутствии)
```

Frontend (из `frontend/`):
```
npm ci
npm run dev
npm run build
npm run test
npm run lint
```

Всё вместе (из корня):
```
docker compose up --build   # поднять панель целиком (backend + frontend + Caddy для HTTPS)
```

## Definition of Done (весь проект)

`cp .env.example .env` (человек заполняет секреты) → `docker compose up` → панель отдаётся
по HTTPS → можно войти (с TOTP), добавить сервер, задать inbound-ы, создать клиента, получить
рабочую subscription-ссылку и QR, увидеть статистику на дашборде. Swagger доступен на `/swagger`.
README объясняет всё. Все тесты и линтеры зелёные.
